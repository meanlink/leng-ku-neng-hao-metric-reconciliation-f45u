# 冷库能耗指标对账

`coldstore-energy-reconcile` 是宁波北仑海风冷链园的月度能耗核算工作台。电表来源、指标版本与来源映射先锁定计算口径，再由 Python 计算实际电量与基准电量的差异率，生成差异复核单。所有复核单关闭后，经理才可以发布月报。

## 业务场景

客户为海风冷链园区能源管理小组，负责 2 座冷库的月度用能盘点。当前流程是从智能电表导出 CSV，能源专员在 Excel 中维护“每吨日耗电”版本，异常靠颜色标记后通过微信群确认。常见问题是单位或周期写错、指标版本被覆盖、复核结论不能追溯。

本系统位于“电表采集 → 月度能耗核算 → 财务/运营月报”的中间环节。上游是智能电表和人工补录，系统产出经过经理签发的月度能耗报告，下游由园区运营和财务使用。

## 模块与流程

- 电表来源：来源编码、站点、单位、周期与抄表入账。
- 指标版本：指标契约、基准 kWh/吨日、容差、生效日期。
- 差异定位：按来源映射校验单位/周期，计算实际、预期、差异率，形成复核单。
- 月报发布：生成草稿，检查复核单关闭与口径兼容后由经理签发。
- 抄表更正单：保留原始抄表，另一人复核通过后以更正值重算并重新开启受影响的差异单。
- 站点能耗预算与结算：按月报内的站点配置电量预算和电价，签发时冻结电量、成本及偏差。
- 供应商账单核验：对照当月站点价表与对账电量，核验供电账单的电量、计费需量及未税小计。退回和重报均保留版本与证据。

主流程是 `抄表 → 指标计算 → 差异复核 → 月报发布`。单位或周期不兼容时拒绝计算/发布，复核单未关闭时拒绝归档。

## 运行

```bash
cp .env.example .env
docker compose config --quiet
docker compose up -d --build
docker compose exec -T backend python -m scripts.seed_demo --with-billing
```

前端 `http://localhost:18249`，后端 `http://localhost:19249/docs`。演示账号密码均为 `coldstore123`。

| 账号 | 角色 | 权限 |
|---|---|---|
| analyst@haifeng.local | 分析员 | 查看、录入来源与抄表、创建指标版本、计算复核单、提出抄表更正、配置站点预算、登记及重报供应商账单 |

## 扩展演示

1. 在「抄表更正单」查看十月 `MTR-HAI-01` 的电表倍率工单 `HF-1026`，提议值由 4,440 更正为 4,100 kWh。
2. 复核员批准。原始读数仍可查，月度有效合计由 12,840 调整为 12,500 kWh。相关差异单重新开启，另一站点的复核状态保留。
3. 在「差异复核」关闭更正后的差异单。从「月报发布」的十月草稿打开「站点结算」，为东港周转冷库配置 6,400 kWh 和 0.76 元/kWh。
4. 经理签发月报，确认东港实际电量 6,500 kWh、实际成本 4,940 元，海风园实际成本 10,250 元。再次查看时可读取签发快照。

更正原因分抄录错误、倍率异常、吞吐吨日复盘。倍率异常只改电量，吞吐复盘只改吨日。驳回记录留档，可以补充证据重提。同一条原表最多有一张待复核或已批准的更正单。

首个站点保存预算后，签发须覆盖该月报差异单中的全部站点。未配置任何站点的月报沿用原发布流程。已签发的预算不可编辑。估算成本按 `电量 × 电价` 四舍五入至分，成本偏差以实际成本减预算成本计算。

## 一月供应商账单演示

1. 经理打开「供应商账单核验」，选 `2027-01`，查看北仑价表 `BL-2027-01-A` 和东港价表 `DG-2027-01-B`。
2. 复核员查阅北仑账单 `BL-2701-017`。实测峰值 169 kW，合同下限 180 kW。账单按 200 kW 收费，未税小计 17,160 元，比核验值高出 720 元。退回时填写供应商重开依据。
3. 分析员登记更正版，确认计费需量 180 kW，未税小计 16,440 元。为东港登记 `DG-2701-008`，电量 6,200 kWh，未税小计 4,772 元。
4. 复核员分别批准两条账单。经理在「月报发布」签发一月月报，再点击「账单核验」查看冻结版和历次退回记录。

电量费按当前月报站点的对账电量乘合同电量单价。需量费取供应商最大需量记录所示峰值与合同下限的较大值，再乘合同需量单价。两项各按四舍五入取到分后加固定费，得到应付未税小计。支持纯电量计费。核验使用账单未税小计和人工录入的最大需量记录依据。

账单电量允许与对账值相差 1 kWh，需量计费站点的计费需量须一致，金额差须在价表容差内。任何一项超差都须退回核实。价表版本更新或对账电量变化后，原审批不能用于签发。待审旧版须先退回，曾获批的旧版可直接重报。价表和账单由同一月度事务锁保护。首张价表启用该月账单核验，之后必须覆盖月报中的全部站点，签发时仅冻结各站点通过复核的最新版。十月抄表更正和预算演示也由 `--with-billing` 初始化。

## 技术结构

五服务为 `frontend`、`backend`、`worker`、`db`、`redis`。后端使用 FastAPI + PyMySQL，数据库使用 MySQL 8.0，前端为原生 HTML/CSS/JavaScript。JWT、审计日志、请求限流分别在 `backend/src/security.py`、`backend/src/services/audit.py` 和 `backend/src/middlewares/__init__.py` 中实现。共享枚举状态在后端路由和前端 `statusTag` 中各自定义。更正原因和决定状态见 `backend/src/closing_schemas.py`、`backend/src/db.py` 与 `frontend/closing.js`。`services/corrections.py` 和 `services/budgets.py` 承载更正与结算规则，新增业务与签发使用同一核算周期事务锁。账单决定在 `backend/src/billing_schemas.py` 和 `frontend/billing.js` 定义，核验差异枚举见 `backend/src/services/bill_math.py` 与 `frontend/billing.js`。为隔离验收环境可用 `COLDSTORE_DB_VOLUME`、`COLDSTORE_REDIS_VOLUME`、`COLDSTORE_ARTIFACT_VOLUME` 指定卷名。

## 算法口径

对每个来源和核算周期，后端汇总实际电量 `actual_kwh = Σ(reading.value × mapping.factor)`，汇总吞吐 `ton_days = Σ(reading.throughput_ton_day)`，预期电量 `expected_kwh = baseline_kwh_per_ton_day × ton_days`，差异率 `difference_rate = (actual_kwh - expected_kwh) / expected_kwh × 100`。输出保留三位小数，输入来自数据库中的抄表与契约记录，可重复计算。计算前执行单位和周期兼容校验，失败返回 422。
